# Implementation Plan: Admin Users, RBAC & Ditto Thing Provisioning

**Branch**: `[009-admin-users-ditto-thing-management]` | **Date**: 2026-05-06 | **Spec**: [spec.md](./spec.md)  
**Input**: Feature specification from `/specs/009-admin-users-ditto-thing-management/spec.md`

## Summary

Introduce **server-enforced identity**, **role and building-scoped authorization**, and **secured REST APIs** to create/read/update/delete (or archive) **Ditto Things** representing elevators. The implementation extends the existing Ditto integration layer (`DittoClient`) with provisioning operations, adds user/role persistence (or IdP integration) as chosen in Phase 0, and adds admin UI surfaces only after contracts and tests exist.

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js ≥22  
**Primary Dependencies**: Express, existing `DittoClient`, JWT (existing dev auth extended or replaced), Zod validation, Vitest  
**Storage**: To be decided in `research.md` — options: PostgreSQL for users/audit, or external IdP + local profile cache  
**Testing**: Contract tests for auth matrix; integration tests with Ditto test double or container; no secrets in snapshots  
**Constraints**: No frontend Ditto access; unified API error shape `{ success, data, error }`; parameterized logging only  
**Scale**: Moderate admin concurrency; provisioning endpoints rate-limited

## Constitution Check

*GATE: Must pass before Phase 0 research. Re-check after Phase 1 design.*

- **Digital Twin authority**: Pass. Ditto remains authoritative for elevator Things; no browser or AI path mutates Twin state directly.
- **Event-driven / reality-tolerant**: Pass where applicable — provisioning is request/response; existing live paths remain event-driven; document Ditto timeout, conflict, and partial-failure handling in `research.md`.
- **Governed schemas / data classes**: Pass. Thing payloads align with `config` / `realtime`-class boundaries; version Zod schemas alongside `contracts/ditto-thing-crud-api.md`.
- **Layered architecture**: Pass. Admin UI → backend APIs → `DittoClient` only; JWT authz enforced server-side.
- **Operational excellence**: Pass. Audit log, structured logs, correlation id, contract + integration tests required before UI ships.
- **Post-design re-check**: Pending until open items in `research.md` are resolved and checklist gate passes.
